## Brainstorming for Quarter 2 Project Proposal


**1. What is the most interesting topic covered in your domain this quarter?**

The most interesting topic that was covered in my domain this quarter was using simulation to teach probability concepts that are difficult to understand from formulas and theoretical concepts. To be more specific, I worked on the St. Petersburg Paradox notebook, and it is a probability concept that is difficult to understand just by learning it through a formula. However, when doing it using simulation, it showed me how the properties, such as its theoretical expected payout, can be very different from what people experience in a limited number of games. Simulating payouts and comparing their mean, median, and distribution was able to showcase to me the influence that rare but extremely large outcomes have, and it was easier to see through this than through learning it a different way. By covering this topic and focusing on this primarily, it's interesting to see how simulation can truly change the way one learns probability.

**2. Describe a potential investigation you would like to pursue for your Quarter 2 Project.**

A potential investigation that I would like to pursue for the Quarter 2 Project is to see whether students writing portions of a simulation by themselves helps them understand probability concepts better than only interpreting the results of a prewritten simulation. This could be done using GradeScope, where we could develop two versions of a certain probability concept. The two versions would be one in which students complete the guided Python code and the other where they work mainly with provided graphs and output. We could compare how well each version supports students' explanations of the probability concepts. The main output of this could be a set of revised educational notebooks and a report evaluating their design and how we could change it based on these results.


**3. What is a potential change you’d make to the approach taken in your current Quarter 1 Project?**

Currently, the notebook that I am doing (St. Petersburg Paradox) is mainly guided, and students complete no code at all. I would want to change my approach by adding more opportunities for students to be able to write meaningful code, but keep the probability concepts as their main focal point. This is because we don't want students to focus on their coding skills, but rather focus on learning the concept itself. It is important for me to balance giving students enough starter code to avoid unnecessary amounts of programming difficulties with being able to let them implement important parts of the simulation. The larger tasks would be broken into smaller steps, so they understand where their code is coming from. This will allow them to learn how the simulation works and the concept itself because being able to understand the simulation is important to learning the concept.

**4. What other techniques would you be interested in using in your project?**

Other techniques that I would be interested in using in my project would be to use more interactive visualizations or even create a Shiny app for my St. Petersburg Paradox. A Shiny app could be something that is important for this because it could be used to visualize the St. Petersburg Paradox even further. This would allow the student to use this app to get a sense of what it actually is. For example, this app could allow students to change the number of trials or the probability of heads and immediately see how those changes affect the distribution of St. Petersburg payouts. This technique could make the notebook be understood even more because it has an app that is also related to it.
